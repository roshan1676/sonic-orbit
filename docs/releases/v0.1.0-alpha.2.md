# SonicOrbit 0.1.0-alpha.2

This alpha addresses the reported AI cancellation problem and hardens Android file selection. It also makes the extension's starting sound less coloured and exposes a useful headphone-profile comparison.

- **Extension:** Studio starts with neutral tone, no room effect and a fully spatial front stage. Clean stereo and Cinema are explicit alternatives. Stage width/centre anchor and Browser/H3/H17 choices are available. A separate two-second direction check tests a known mono object. Upgrading resets the older coloured settings once; restored volume remains capped at 50%.
- **Renderer/SDK:** measured profiles now cover ordinary stereo front speakers and the centre anchor, in addition to scene objects. Room reflections and optional rear ambience retain browser HRTF. Desktop profile selection works before preparing AI tracks.
- **AI cancellation, issue #2:** Cancel stays visible, becomes usable at startup and remains available through job polling, audio initialization and stem download/decode. Requests have timeouts, failed polling retains Cancel, late work cannot activate a cancelled scene, and reopening the same file exposes its active job. Complete cached tracks are preserved.
- **Android file selection, issue #1:** a native Open button works independently of the Web Audio module; a small bootstrap also keeps the in-page button and callbacks available if renderer loading fails. Picker launch failures show an explanation, repeated launches are guarded and copy completion restores the native button. The reported device still needs retesting: the original phone failure was not reproduced here.
- **Documentation:** [sound-quality goals and a practical listening protocol](../audio-quality.md), with the larger remaining work stated explicitly.

## Validation

40 automated tests pass with the bundled Node 24 runtime. The browser audio suite contains 31 render/worker checks. Android packaging/signature verification is performed during the build; this is not a real phone test. Real installed-extension capture is not automated here. The Windows launcher execution limitation from alpha 1 remains: the bundled server/UI can be tested directly, but the launcher itself was previously blocked from runtime testing by automatic approval review.

The Android development package uses version code 2, and Chromium uses numeric extension version 0.1.1 with version name 0.1.0-alpha.2 so existing installs can update. The APK retains the same local development signing key as alpha 1 on this build machine.

This release does not add AI separation or live head tracking to the extension/APK, native engine plugins, cross-app Android effects, recovered Atmos objects, personalized ear models or demonstrated superiority over another product. Perceived quality remains to be assessed by listeners.
